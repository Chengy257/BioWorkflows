> 适用对象：需要在本集群/服务器上运行该流程的分析人员

---

## 1. 功能概述

本流程面向 bulk RNA-seq（有参考基因组）数据，提供四条管线：

| 入口文件 | 管线内容 | 产物 |
|---|---|---|
| `RNA-seq_upstream_only.smk` | 质控→比对→基因定量 | 清洗数据、BAM、count 矩阵、TPM 表 |
| `RNA-seq_up_DEG.smk` | 上游 + 差异表达 + 富集 | DEG 结果、GO/KEGG/GSEA、组间比较 |
| `RNA-seq_up_AS.smk` | 上游 + StringTie 转录本组装/定量 | 各样本组装 GTF、merged GTF、isoform 定量 |
| `RNA-seq_up_lncRNA.smk` | 上游 + de novo lncRNA 鉴定 | 候选 lncRNA 集合及其表达矩阵 |

分析主线：`FastQC → Trim Galore →（链特异性推断）→ STAR two-pass 比对 → featureCounts 定量 → DESeq2 差异分析 → clusterProfiler GO/KEGG 富集 + GSEA`。

流程 DAG 参考：[dag.svg](../rna-seq-workflow/dag.svg)（上游+DEG）、[dag_lnc.svg](../rna-seq-workflow/dag_lnc.svg)（lncRNA）。

## 3. 运行前准备

### 3.1 目录与数据约定

在工作目录（如 `/path/to/project/mRNA`）下：

```
project/
├── 1.rawdata/                     # 原始测序数据（自行放置）
│   ├── {sample}_1.fastq.gz        # 双端：R1/R2 命名为 {sample}_1 / {sample}_2
│   └── {sample}_2.fastq.gz
│   └── {sample}.fastq.gz          # 或单端：{sample}.fastq.gz
├── sample_info.csv                # 样本分组表（复制模板后修改）
└── config_user_defined.yaml       # 用户配置
```

⚠️ **样本 ID 命名规则（当前代码的实际约束，违规则出错）**：
1. **样本 ID 之间不得互为前缀**（如 `ctal_1` 与 `ctal_1_1` 并存会导致文件误匹配）；
2. 样本 ID **不要含 `-`**（差异分析环节只对样本表做 `-`→`_` 替换，count 矩阵不做，会列名不匹配）；
3. 含 `_` 的样本 ID 会使 `3.align/mapping_stat.xls` 的 ID 列被截断（P0-6，待修复）——**阶段 1 之前建议样本 ID 完全不含下划线**；
4. 样本 ID 不要含 `.`。

### 3.2 样本分组表 `sample_info.csv`

两列，无行名：

```csv
id,group
WT_1,control
WT_2,control
WT_3,control
drugA_1,drugA
drugA_2,drugA
drugA_3,drugA
```

⚠️ **当前版本必须包含名为 `control` 的组**：DESeq2 环节只输出"各组 vs control"的比较，`control` 为硬编码组名（P0-7）；组间交叉比较（`6.DEGcompare`）也以 vs control 结果为输入。

### 3.3 用户配置 `config_user_defined.yaml`

在默认配置（`config_basic_defaulted.yaml`）基础上，用户配置至少提供：

```yaml
threads: "12"                       # 每任务线程数（默认配置中被注释，必须由用户配置提供）
gtf: "/path/to/reference.gtf"       # 基因注释（比对索引构建、定量均使用）
genome: "/path/to/genome.fa"        # 参考基因组
bed: "/path/to/transcripts.bed"     # 仅 AS 管线需要：链特异性推断用 bed（需与基因组匹配）
SampleListFile: "sample_info.csv"   # 样本表文件名（相对工作目录）
FoldChange: "2"                     # 差异倍数阈值
padj: "0.05"                        # 显著性阈值
```

lncRNA 管线另需 `config_lncRNA.yaml` 中的：`gtf_PcGs`（蛋白编码参考，用于 gffcompare 过滤）、`pfam_DB`（Pfam-A HMMPfam 数据库目录）、`nr_diamond_DB`（diamond 格式化好的 nr 库）。

### 3.4 主控脚本 `main_runRNA-seq.sh`

复制到项目并修改以下变量（**当前脚本内是作者个人路径，必须逐项核对**）：

```bash
smk=/path/to/rna-seq-workflow/RNA-seq_upstream_only.smk   # 选择入口（见第 1 节表格）
conda_path=/opt/anaconda3/                                 # conda 安装路径
DIR=/path/to/project/mRNA                                  # 工作目录
config=$DIR/config_user_defined.yaml                       # 用户配置
job_title=rna-xxx                                          # SGE 作业名前缀
```

当前调度参数为 SGE：`--cluster "qsub -V -N $job_title -l ncpus=12 -j oe"`，并行度 `-j 3 --cores 36`，按集群实际负载修改。

## 4. 运行与监控

```bash
# 1. 修改并执行主控脚本（前台运行，日志追加至 snakemake.logs.txt）
bash main_runRNA-seq.sh

# 2. 推荐先 dry-run 检查（不会真正提交作业）
cd $DIR && snakemake -s $smk --configfile $config -n --quiet

# 3. 查看进度与日志
tail -f $DIR/snakemake.logs.txt
ls $DIR/logs/                       # 各步骤日志
```

断点续跑：Snakemake 依据输出文件自动跳过已完成步骤；重跑单个文件可 `snakemake -s $smk --configfile $config -R <rule> -n` 先预览。

## 5. 结果解读

> 以下为当前输出目录约定（路径硬编码于规则中，阶段 2 将参数化）。

| 目录/文件 | 内容 |
|---|---|
| `2.cleandata/trim/` | 接头修剪后 fastq；`*_trimming_report.txt` 为修剪报告 |
| `2.cleandata/trim/fastqc/multiqc_report.html` | 清洗后 QC 汇总（**upstream/DEG 管线当前为空报告，见第 6 节**） |
| `3.align/{sample}_Aligned.sortedByCoord.out.bam(.bai)` | 比对结果（经 samtools sort/index） |
| `3.align/{sample}_Log.final.out` | STAR 比对统计原文 |
| `3.align/{sample}.strandedness` | 链特异性推断结果（firststrand/secondstrand/unstrand） |
| `3.align/mapping_stat.xls` | 汇总比对统计（**当前版本对含下划线/双端样本存在错位，见第 6 节**） |
| `4.expression/{sample}.count` | 单样本 featureCounts 定量（id/effLength/counts/fpkm/tpm 五列） |
| `4.expression/count.matrix.tsv` | 原始 count 矩阵（DESeq2 输入） |
| `4.expression/GeneExpression_TPM.xls`（及 FPKM） | 表达量矩阵 |
| `5.DEG/Diff_Expr_Analysis_Reults/` | 差异分析：样本聚类热图、PCA、各 `{treat}_vs_{control}_DESeq2.output.tsv`、火山图/MA 图 |
| `5.DEG/DEGs/` | 各比较的 UP/DOWN/ALL DEG 基因列表及注释 |
| `5.DEG/GO_KEGG_enrich/` | GO(MF/BP/CC)/KEGG 富集全量与显著结果、dotplot、网络图与通路聚类 |
| `5.DEG/GSEA_enrich_GO/` | GSEA 结果 |
| `6.DEGcompare/` | 组间 DEG 集合交集（venn/upset）与交叉富集比较 |
| `4.assembly/`（AS 管线） | StringTie 各样本组装、`merged.gtf`、gffcompare 报告、isoform FPKM/TPM |
| `4.LncRNA/`（lncRNA 管线） | 编码势过滤中间产物、Pfam/NR 比对命中、`4.5.Final_lncRNA/final_lncRNA.fa/gtf` |
| `logs/` | 各规则日志 |

差异结果文件 `*_DESeq2.output.tsv` 列说明：`baseMean, log2FoldChange, lfcSE, stat, pvalue, padj, FoldChange, 各样本标准化count, type(Up/Down/Unsig)`；判定阈值 `padj ≤ 0.05 且 FC ≥ 2（或 ≤ 1/2）`，可在 config 中修改。

## 7. 常见问题（FAQ）

**Q1：单端测序能跑吗？**
能。rawdata 放 `{sample}.fastq.gz` 即可，流程以文件数自动判断 SE/PE；但建议等待阶段 1.5 改为显式声明后再使用（当前自动判断在文件数异常时会给出隐晦报错）。

**Q2：批次效应怎么处理？**
`runDESeq2_multiGroup_230705.R` 支持 `-b T`（样本表需第三列 batch，设计为 `~ batch + group`）。当前 Snakemake 规则固定传 `-b F`，需要批次校正时需临时修改 `rules/RNA-seq_downstream.smk:63`。

**Q3：如何只补跑差异分析？**
count 矩阵已存在时，直接以 `RNA-seq_up_DEG.smk` 为入口运行即可，上游会自动跳过。

**Q4：能换物种吗？**
比对/定量层面只需更换 config 中 `gtf/genome/bed`；**差异富集层面当前写死水稻**（OrgDb、KEGG code、注释文件），换物种需修改脚本或等待阶段 1.6 的 species.yaml 方案。

**Q5：为什么我的差异结果只有 vs control？**
当前版本设计如此（P0-7）。任意两两比较由 `6.DEGcompare` 基于 DEG 集合做交集/富集比较，不输出直接的两两 DESeq2 结果表。
