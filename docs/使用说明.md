# RNA-seq 工作流使用说明

> 更新日期：2026-09-03（对应 v0.2.0，阶段 1 修复已完成）
> 适用对象：需要在本集群/服务器上运行该流程的分析人员
> 本次更新修复了原 8 个阻断性问题（P0）：路径已参数化、conda 环境已入库、比对统计已修正、对照组与物种已配置化。**首次运行前必须把配置中的 `/path/to/...` 占位符替换为真实路径。**

---

## 1. 功能概述

本流程面向 bulk RNA-seq（有参考基因组）数据，提供四条管线：

| 入口文件 | 管线内容 | 产物 |
|---|---|---|
| `RNA-seq_upstream_only.smk` | 质控→比对→基因定量 | 清洗数据、BAM、count 矩阵、TPM 表 |
| `RNA-seq_up_DEG.smk` | 上游 + 差异表达 + 富集 | DEG 结果、GO/KEGG/GSEA、组间比较 |
| `RNA-seq_up_AS.smk` | 上游 + StringTie 转录本组装/定量 | 各样本组装 GTF、merged GTF、isoform 定量 |
| `RNA-seq_up_lncRNA.smk` | 上游 + de novo lncRNA 鉴定 | 候选 lncRNA 集合及其表达矩阵 |

分析主线：`FastQC → Trim Galore →（链特异性推断）→ STAR two-pass 比对 → featureCounts 定量 → DESeq2 差异分析 → clusterProfiler GO/KEGG 富集 + GSEA`。

流程 DAG 参考：[dag.svg](../rna-seq-workflow/dag.svg)（上游+DEG）、[dag_lnc.svg](../rna-seq-workflow/dag_lnc.svg)（lncRNA）。

## 2. 系统要求

| 依赖 | 说明 |
|---|---|
| Linux（SGE 集群或单机） | 有 `qsub` 自动走 SGE profile，否则本地多核运行；可用 `RUN_PROFILE` 环境变量强制指定 |
| Snakemake ≥ 7 | `conda install -c conda-forge snakemake` |
| conda/mamba | `--use-conda` 按需自动构建 `envs/*.yaml` 中的 7 个环境（首次运行会下载，耗时较长） |
| 外部工具（conda 外） | CPC2、CNCI、pfam_scan.pl 为个人安装工具，路径在 `config_lncRNA.yaml` 配置（`cpc2_bin`/`cnci_dir`）；pfam_scan.pl 需在 PATH |
| python3（可选） | 用于运行前样本表校验 |

## 3. 运行前准备

### 3.1 目录与数据约定

在工作目录（如 `/path/to/project/mRNA`）下：

```
project/
├── 1.rawdata/                     # 原始测序数据（自行放置）
│   ├── {sample}_1.fastq.gz        # 双端：R1/R2 命名为 {sample}_1 / {sample}_2
│   └── {sample}_2.fastq.gz
│   └── {sample}.fastq.gz          # 或单端：{sample}.fastq.gz
├── sample_info.csv                # 样本分组表
└── config_user_defined.yaml       # 用户配置（可选）
```

⚠️ **样本 ID 命名规则（违规则校验失败或结果异常）**：
1. 样本 ID **不得含 `-`**（校验器直接报错）；
2. 样本 ID 之间**尽量避免互为前缀**（如 `ctal_1` 与 `ctal_1_1` 并存会触发校验警告——现在文件匹配用精确文件名，不再误配，但仍建议改名）；
3. 样本 ID 不要含空格、`/`、`.`。

### 3.2 样本分组表 `sample_info.csv`

列：`id,group`，可选 `layout`（`PE`/`SE`/`auto`，当前版本以实际文件探测为准，`auto` 即可）：

```csv
id,group,layout
WT_1,control,auto
WT_2,control,auto
WT_3,control,auto
drugA_1,drugA,auto
drugA_2,drugA,auto
drugA_3,drugA,auto
```

- 对照组名由配置 `control_group` 指定（默认 `control`）；差异分析输出 `各组_vs_{对照组}` 比较，组间交叉比较（`6.DEGcompare`）以其为输入。
- 运行前可用校验器自查：`python3 rna-seq-workflow/scripts/validate_samples.py sample_info.csv control`（`run.sh` 启动时也会自动执行）。

### 3.3 配置

默认配置 `config_basic_defaulted.yaml` 已包含全部必需键，**其中 `/path/to/...` 为占位符，首次运行必须替换**：

| 键 | 说明 |
|---|---|
| `SampleListFile` | 样本表文件名（相对工作目录） |
| `control_group` | 对照组组名 |
| `threads` | 每任务线程数 |
| `FoldChange` / `padj` | 差异倍数 / 校正 p 值阈值 |
| `species` | `osa`（水稻）或 `hsa`（人），决定 GO 注释 keyType 与 KEGG 物种代码 |
| `bed` | RSeQC 链型推断用 bed |
| `genome` / `gtf` | 参考基因组 / 注释（STAR 建库、featureCounts、stringTie 共用） |
| `annotation_tsv` | 基因 id 功能注释表（DEGs 注释用） |
| `orgdb_tarball` | osa 本地 OrgDb tarball（species=hsa 时忽略） |

lncRNA 管线另需 `config_lncRNA.yaml`：`gtf`（lncRNA 流程参考注释，覆盖基础配置）、`gtf_PcGs`、`pfam_DB`、`nr_diamond_DB`、`cpc2_bin`、`cnci_dir`、`lncrna_threads`。

需要覆盖配置时，复制 `config_user_defined.yaml` 模板修改，只写要覆盖的键即可（未写的键回落到默认配置）。

### 3.4 启动脚本 `run.sh`

```bash
bash run.sh <pipeline> <project_dir> [user_config.yaml] [jobs]
# pipeline: upstream | deg | as | lncrna
# 例：bash run.sh deg /path/to/project/mRNA my_config.yaml 10
```

脚本行为：
1. 自动校验样本表（校验失败即停止）；
2. 自动选择调度 profile：有 `qsub` 用 SGE（`profile/sge`），否则本地（`profile/default`）；
3. 配置优先级：命令行 config > 项目目录 `config_user_defined.yaml` > 工作流默认配置；
4. 日志写入 `$project_dir/snakemake.logs.txt`。

旧版 `main_runRNA-seq.sh` 已删除（其硬编码路径与 `tee -a >>` 双重追加写法已废弃），如需自定义调度参数，直接复制 `profile/sge/config.yaml` 修改。

## 4. 运行与监控

```bash
# 1. dry-run 预览（不真正执行）
cd /path/to/project && snakemake -s /path/to/rna-seq-workflow/RNA-seq_up_DEG.smk --configfile my_config.yaml -n --quiet

# 2. 正式运行
bash /path/to/rna-seq-workflow/run.sh deg /path/to/project my_config.yaml 10

# 3. 查看进度与日志
tail -f snakemake.logs.txt
ls logs/                            # 各步骤日志
qstat                               # SGE 作业队列
```

断点续跑：Snakemake 依据输出文件自动跳过已完成步骤；首次运行会先构建 conda 环境（每环境一次，耐心等待）。

## 5. 结果解读

| 目录/文件 | 内容 |
|---|---|
| `2.cleandata/trim/` | 接头修剪后 fastq；`*_trimming_report.txt` 为修剪报告 |
| `2.cleandata/trim/fastqc/multiqc_report.html` | 清洗后 QC 汇总（**upstream/DEG 管线当前仍为空报告，见第 6 节**） |
| `3.align/{sample}_Aligned.sortedByCoord.out.bam(.bai)` | 比对结果（经 samtools sort/index） |
| `3.align/{sample}_Log.final.out` | STAR 比对统计原文 |
| `3.align/{sample}.strandedness`（及 `_infer_experiment.out`） | 链特异性推断结果 |
| `3.align/mapping_stat.xls` | 汇总比对统计（v0.2.0 起逐样本解析，**ID 保留完整、PE 不再错位**；Total_Reads 为 trim 报告 R1 读数=PE 读对数） |
| `4.expression/{sample}.count` / `{sample}.log` | 单样本 featureCounts 定量（5 列）与状态统计 |
| `4.expression/count.matrix.tsv` | 原始 count 矩阵（DESeq2 输入） |
| `4.expression/GeneExpression_TPM.xls` / `_FPKM.xls` | 表达量矩阵 |
| `4.expression/GeneCount_Assigned_logs.xls` | 各样本比对到特征的 Assigned/Unassigned 统计 |
| `5.DEG/Diff_Expr_Analysis_Reults/` | 差异分析：聚类热图、PCA、各 `{treat}_vs_{control}_DESeq2.output.tsv`、火山图/MA 图 |
| `5.DEG/DEGs/` | 各比较的 UP/DOWN/ALL DEG 基因列表及注释 |
| `5.DEG/GO_KEGG_enrich/` / `GSEA_enrich_GO/` | 富集与 GSEA 结果 |
| `6.DEGcompare/` | 组间 DEG 集合交集（venn/upset）与交叉富集比较 |
| `4.assembly/`（AS 管线） | StringTie 组装、`merged.gtf`、gffcompare 报告、isoform FPKM/TPM |
| `4.LncRNA/`（lncRNA 管线） | 编码势过滤中间产物、Pfam/NR 命中、`4.5.Final_lncRNA/final_lncRNA.fa/gtf` |
| `5.expression/lncRNA/`（lncRNA 管线） | lncRNA+参考基因的定量矩阵 |
| `logs/` | 各规则日志 |

差异结果 `*_DESeq2.output.tsv` 列：`gene_id, baseMean, log2FoldChange, lfcSE, stat, pvalue, padj, FoldChange, 各样本标准化count, type(Up/Down/Unsig)`；阈值 `padj ≤ 0.05 且 FC ≥ 2（或 ≤ 1/2）`，由 config 的 `padj`/`FoldChange` 控制。

## 6. 已知限制与注意事项（v0.2.0）

| # | 事项 | 影响 | 建议 |
|---|---|---|---|
| 1 | upstream/DEG 管线的 trim 规则未运行 FastQC | MultiQC 清洗后报告为空 | 手动对 `2.cleandata/trim/*.fq.gz` 运行 fastqc+multiqc，或等阶段 2 统一 trim 规则（AS 管线已带 --fastqc） |
| 2 | KEGG 富集依赖 KEGG REST API 外网访问 | 无外网节点该步自动跳过（GO 结果不受影响） | KEGG 结果在可联网节点补跑，或等阶段 2 离线方案 |
| 3 | 差异比较命名 `{treat}_vs_{control}` | 对照组名含 `_` 时下游前缀解析可能异常 | 对照组名避免下划线 |
| 4 | 批次校正参数固定 `-b F` | 需要批次校正时不起效 | 临时改 `rules/RNA-seq_downstream.smk` 中 runDESeq2 的 `-b` 参数，或等阶段 2 配置化 |
| 5 | 两条上游管线的原始 fastq 命名约定不同 | upstream 管线认 `.fastq.gz`，AS 管线认 `.fq.gz`（双端 R1/R2 均支持 `_1/_2`） | 按管线约定命名，或做软链接 |
| 6 | CNCI 需 Python2 环境、pfam_scan.pl 不经 conda 管理 | 环境缺失时 lncRNA 管线对应步骤失败 | 按 `config_lncRNA.yaml` 配好外部工具路径 |
| 7 | `mapping_stat.xls` 的 Total_Reads 取 trim 报告 R1 数（即 PE 读对数） | 与单端样本的"读数"口径不同 | 解读时注意；详细读数以 `*_trimming_report.txt` / `*_Log.final.out` 原文为准 |

完整问题清单（P0×8 / P1×14 / P2×9）见 [审查报告](审查报告.md)；后续计划见 [优化路线图](优化路线图.md)。

## 7. 常见问题（FAQ）

**Q1：单端测序能跑吗？**
能。rawdata 放 `{sample}.fastq.gz`（或 `.fq.gz`），流程按精确文件名自动探测 SE/PE；样本表可加 `layout` 列说明，但以实际文件为准。

**Q2：批次效应怎么处理？**
`runDESeq2_multiGroup_230705.R` 支持 `-b T`（样本表需第三列 batch，设计为 `~ batch + group`）。当前规则固定传 `-b F`（见第 6 节 #4）。

**Q3：如何只补跑差异分析？**
count 矩阵已存在时，直接以 `RNA-seq_up_DEG.smk` 为入口运行即可，上游自动跳过。

**Q4：能换物种吗？**
能（osa/hsa）。比对/定量层面更换 config 中 `genome/gtf/bed`；富集层面设置 `species: hsa` 即自动切换 org.Hs.eg.db + ENSEMBL keyType + KEGG hsa（基因 id 自动去版本号）。其他物种需自制 OrgDb 并参照 `enrich_GO_KEGG_clusterProfiler_gProfilerGO.R` 扩展。

**Q5：为什么我的差异结果只有 vs control？**
当前设计如此：DESeq2 只输出"各处理组 vs 对照组"（对照组名 = `control_group` 配置）。任意两两比较由 `6.DEGcompare` 基于 DEG 集合做交集/富集比较。

**Q6：conda 环境构建失败怎么办？**
查看 `~/.conda/envs` 下的报错；常见原因是网络（改用镜像源）或 `envs/*.yaml` 中的版本号在当前频道不可用（可放宽 pin）。CPC2/CNCI/pfam_scan.pl 不在 conda 环境内，见第 6 节 #6。
