# ChIP/CUT&Tag/ATAC/FAIRE 工作流使用说明

> 更新日期：2026-09-04（对应 v0.4.0，统一环境 + run.sh 运维 CLI）
> 适用对象：需要在本集群/服务器上运行该流程的分析人员
> v0.4.0 起不再按 rule 自动创建多个 Conda 环境：运行环境统一按 `workflow/environment.yaml` 创建，或经 `config/software.yaml` 复用服务器已有环境与 R 库；集群调度资源按 rule 声明并支持项目级覆盖。

---

## 1. 安装与环境准备

### 1.1 前置要求

| 依赖 | 说明 |
|---|---|
| Linux（PBS/SGE/SLURM 集群或单机） | 调度器由 `run.sh` 自动探测或 `--profile` 指定 |
| Snakemake | 参考版本 **7.32.4**（`workflow/environment.yaml` 钉版）；版本矩阵见 §1.4 |
| Python 3 + PyYAML | `run.sh` 解析 `software.yaml` 与运行前检查的**自举依赖**，须在主 PATH 可用 |
| 分析工具 | fastqc / trim_galore / multiqc / bowtie2 / samtools / picard / macs2 / bedtools / deeptools / phantompeakqualtools / R（ChIPseeker、GenomicFeatures） |

启动器自举顺序：`run.sh` 先用系统 PATH 上的 `python3`（需含 PyYAML）解析 `config/software.yaml`，再把主环境/工具注入当前进程——因此即使走 conda_prefix 复用路线，登录节点 PATH 上也必须有 `python3` 与 `snakemake`（解析后由主环境提供）。

### 1.2 环境三条落地路径

**路径一：全新服务器，按一体化环境模板创建**

```bash
mamba env create -f workflow/environment.yaml   # 环境名 chip-cuttag-atac-faire
conda activate chip-cuttag-atac-faire
```

该命令由用户显式执行；Snakemake 不会自动创建或修改软件环境。模板钉版：snakemake-minimal 7.32.4、fastqc 0.12.1、trim-galore 0.6.10、multiqc 1.14、bowtie2 2.5.1、samtools 1.17、picard 3.0.0、macs2 2.2.7.1、bedtools 2.31.0、deeptools 3.5.1、phantompeakqualtools 1.2.2、r-base 4.3、bioconductor-chipseeker 1.38.0、bioconductor-genomicfeatures 1.54.0。

**路径二：复用服务器已有 conda 环境**

把 `config/software.yaml` 复制到项目目录（或直接改仓库默认），设置：

```yaml
environment:
  type: conda
  conda_prefix: "/share/conda/envs/chip-cuttag-atac-faire"   # HPC 推荐 prefix
  # conda_name: "chip-cuttag-atac-faire"                     # 或按环境名解析
  strict: true
```

无需 `conda activate`：`run.sh` 解析后把该 prefix 的 `bin` 注入 PATH。路径一创建的环境也可以用这种方式对接（此时 `environment.yaml` 只承担"建环境"职责，运行时统一走 `software.yaml`）。

**路径三：system 模式 + 复用服务器已有 R 库**

工具全部走系统 PATH、R 单独安装时：

```yaml
environment:
  type: system
  strict: true

r:
  rscript: "/opt/R/4.3/bin/Rscript"   # 也可写 "Rscript" 走 PATH
  version: "4.3"                       # 可选校验
  version_check: major_minor           # major_minor | exact | warn | off
  lib_paths:                           # 复用服务器已有 ChIPseeker 等库
    - "/share/Rlibs/4.3"
  lib_mode: prepend                    # prepend | append | replace
```

`r.lib_paths` 经 `R_LIBS_USER` 传给所有 R 步骤；`prepend` 不会遮蔽 R 自身的 base/site library。conda 环境里已含 ChIPseeker/GenomicFeatures 时无需此段。

### 1.3 运行前检查（preflight）

```bash
# 检查可执行工具、R、R 包是否全部解析成功（然后退出）
bash run.sh -P /path/to/workdir --check-software

# 只检查配置的 Rscript、R 版本与 R 包
bash run.sh -P /path/to/workdir --check-r

# 解析 workflow + 全部 config（样本表/配置校验在解析期执行），列出规则后退出，不启动任务
bash run.sh -P /path/to/workdir -c /path/to/workdir/config.yaml --validate-only
```

说明：

- `--check-software` / `--check-r` 需要 `-P` 指定项目目录（目录不存在会自动创建）；
- 正式运行前 `run.sh` 会**自动**执行一次完整 preflight；`--skip-software-check` 可跳过，`-n`（dry-run）自动跳过；
- `software.yaml` 查找顺序：`--software FILE` > `<项目目录>/software.yaml` > 仓库 `config/software.yaml`。`tools:` 段仅需覆盖有差异的工具（deeptools 工具组以 `bamCoverage` 为代表二进制、SPP 入口为 `run_spp.R`，均已预填 bioconda 包内的命令名）。

### 1.4 Snakemake 版本矩阵

| snakemake 版本 | 支持情况 | 说明 |
|---|---|---|
| **7.32.4** | ✅ 参考版本 | `workflow/environment.yaml` 钉版；集群 profile（pbs/sge/slurm）以 7.x 经典 `--cluster` 接口为准 |
| **8.x** | ⚠️ 集群语义未验证 | 统一环境下解析/lint 级已验证；8.x 改用 executor 插件体系（`--cluster` 语义移除），launcher 启动时会打印告警，集群实跑前先实测 |
| <7 或 ≥9 | ⛔ 未验证 | 需实测 |

## 2. 快速开始

五步跑通一个最小项目（以水稻示例为参照，换物种改参考文件即可）：

**步骤 1：建工作目录**

```bash
mkdir -p ~/work/chip_demo/1.rawdata
```

工作目录（数据）与分析代码目录（本仓库）分离，`run.sh` 会在工作目录内生成全部结果。

**步骤 2：放入原始数据**

fastq 命名为 `{sample}_1.fq.gz` / `{sample}_2.fq.gz` 放入 `1.rawdata/`。常见 `_R1.fastq.gz`/`_1.fastq.gz` 等后缀可交给启动器批量重命名：

```bash
cp my_*.fastq.gz ~/work/chip_demo/1.rawdata/
bash run.sh -P ~/work/chip_demo -r        # -r 仅在存在 1.rawdata/ 时生效，perl rename 语法
```

**步骤 3：编写样本表**

```bash
cp config/samples.csv ~/work/chip_demo/sample_info.csv
```

编辑该文件填入自己的样本（6 列 schema 与校验规则见 §3）。注意 `config.yaml` 的 `grouplist` 默认值为 `config/samples.csv`（仓库模板），**相对路径优先在工作目录解析**——样本表文件名可以自定，改 `grouplist` 指向即可。

**步骤 4：编写项目配置**

```bash
cp config/config.yaml ~/work/chip_demo/config.yaml
```

把参考基因组四件套（`genome_fa` / `gtf` / `bed` / `chromsize`）与 `genome_size`（MACS2 有效基因组大小）改为自己的物种。`run.sh` 对 `-c` 缺省时会自动探测 `<项目目录>/config.yaml`，因此放在工作目录即可生效。全键说明见 §4。

**步骤 5：预检并启动**

```bash
cd /path/to/repo
bash run.sh -P ~/work/chip_demo --check-software   # 环境预检
bash run.sh -P ~/work/chip_demo -n                 # dry-run：构建 DAG 并打印计划任务，不执行
bash run.sh -P ~/work/chip_demo -j 10              # 正式运行（本机/自动探测调度器）
```

启动成功后主日志在 `~/work/chip_demo/snakemake.logs.txt`（`--log FILE` 可改），各步骤日志在 `logs/`。结果目录见 §7。

## 3. 样本表详解

样本表为 6 列 CSV（模板 `config/samples.csv`，混型示例可直接参照）：

```csv
sample_id,role,group,seqtype,layout,peak_type
myc,treat,myc_vs_IgG,chip,PE,narrow
IgG,control,myc_vs_IgG,chip,PE,narrow
H3K27me3_rep1,treat,H3K27me3_vs_IgG,cuttag,PE,broad
IgG_cuta,control,H3K27me3_vs_IgG,cuttag,PE,broad
atac_leaf_1,treat,atac_leaf,atac,PE,none
atac_leaf_2,treat,atac_leaf,atac,PE,none
faire_root,treat,faire_root_vs_Input,faire,PE,none
Input_faire,control,faire_root_vs_Input,faire,PE,none
```

### 3.1 列定义

| 列 | 取值 | 说明 |
|---|---|---|
| `sample_id` | 非空 | 样本名，须与 `1.rawdata/` 中 fastq 前缀一致 |
| `role` | `treat` / `control` | 处理组 / 对照组；**对照组（IgG/Input）也要列入**，对照同样需要比对 |
| `group` | 非空 | 峰调用分组名；同一分组可含多个 treat 与多个对照（MACS2 多文件输入 `-c`） |
| `seqtype` | `chip` / `cuttag` / `atac` / `faire` | assay 类型，按行混填即混型项目 |
| `layout` | `PE` | 当前版本仅支持双端 |
| `peak_type` | `narrow` / `broad` / `none` | chip/cuttag 的处理组须填 `narrow` 或 `broad`；atac/faire 固定填 `none`（峰型由流程决定） |

### 3.2 校验规则（解析期逐行执行，错误信息含行号）

校验在 Snakemake 解析期集中执行（`workflow/rules/common.smk` 的 `load_sample_table`），任何一条不满足即中断并指出行号：

1. 必须包含全部 6 列，缺列直接报错并列出缺失列名；
2. `sample_id` / `group` 非空，且仅允许**字母数字与 `. _ -`**：须以字母数字开头、不得以 `-` 开头、**不含连续下划线 `__`**（`__` 是 FRiP 输出文件名分隔符；逗号/空格会破坏峰列表拼接与 shell 展开）；
3. `role` 只接受 `treat`/`control`；`seqtype` 只接受四种 assay；`layout` 只接受 `PE`；`peak_type` 只接受 `narrow`/`broad`/`none`；
4. atac/faire 行的 `peak_type` 必须为 `none`；chip/cuttag 的 **treat** 行必须为 `narrow` 或 `broad`；
5. 同一 `sample_id` 不得出现在不同 `seqtype` 的分组中；
6. 同一 `group` 内各行 `seqtype` / `peak_type` / `layout` 必须一致；
7. 每个分组至少含 1 个 `role=treat` 的样本；全表至少 1 行数据。

### 3.3 混型说明

- 四种 assay 按行混填，无需任何启动参数；`seqtype` 列驱动全流程路由（去重策略、峰调用规则，见 §5.1）；
- chip 与 cuttag 可以共用同一 `group` 名吗——**不行**：同一 `group` 内 `seqtype` 必须一致（规则 6），不同 assay 请用不同分组；
- 样本表路径由 config 的 `grouplist` 指定：绝对路径 > 工作目录相对路径 > 仓库目录相对路径。若三处都找不到文件，解析期**直接报错**（v0.4.0 起不再静默回落开发示例）；真实项目示例见 `example/samples.csv`。

## 4. 配置详解

### 4.1 配置链与叠加

`run.sh` 按以下顺序组装 `--configfile` 链，**靠后者覆盖靠前者同键**：

1. 仓库默认 `config/config.yaml`（恒在链首，兜底）；
2. 项目配置：`-c FILE` 显式指定；未指定时自动探测 `<项目目录>/config.yaml`；
3. 叠加配置：`-l FILE` 显式指定；未指定时自动检测 `<项目目录>/config.local.yaml`（检测到会打印 INFO）。

典型用法：项目配置只放"项目差异项"，机器相关差异（如线程数）放 `config.local.yaml`（不进版本库）；仓库 `config/config.template.yaml` 是带注释的可覆盖模板，复制为 `config.local.yaml` 改差异项即可（所有键均可选，未列键沿用默认）。

### 4.2 config.yaml 全键

| 键 | 默认 | 说明 |
|---|---|---|
| `genome_fa` | 水稻 IRGSP-1.0 示例路径 | bowtie2 建索引输入（**换物种必改**） |
| `gtf` | 同上 | 峰注释（ChIPseeker makeTxDbFromGFF）用 |
| `bed` | 同上 | deeptools 基因区信号用 |
| `chromsize` | 同上 | bigWig 生成用（染色体长度表） |
| `genome_size` | `"3.7e8"` | MACS2 有效基因组大小（水稻约 3.7e8；**换物种必改**，人类 2.7e9、小鼠 1.87e9） |
| `grouplist` | `config/samples.csv` | 样本表路径（相对工作目录解析，见 §3.3） |
| `threads` | `12` | 单任务线程数（整数、不加引号；callpeak 类规则固定 1 线程，MACS2 单线程程序） |
| `trim.quality` | `25` | trim_galore `-q` 末端低质量碱基阈值 |
| `trim.stringency` | `3` | 接头最少重叠碱基数 |
| `trim.error_rate` | `0.1` | `-e` 接头匹配最大错误率 |
| `trim.extra` | `""` | 追加参数，如 `"--clip_r1 5 --clip_r2 5"` |
| `bowtie2_extra` | `--end-to-end --very-sensitive --no-mixed --no-discordant --phred33 -I 10 -X 700` | bowtie2 参数串 |
| `min_mapq` | `30` | 比对质量过滤阈值（ENCODE 常规值） |
| `dedup.chip` / `dedup.atac` / `dedup.faire` | `true` | picard MarkDuplicates 去重开关（按 assay） |
| `dedup.cuttag` | `false` | CUT&Tag 不去重（保留 PCR 重复，Kaya-Okur et al. 2019） |
| `peak.keepdup` | `all` | MACS2 层面保留全部重复（去重交给上游 dedup 策略控制） |
| `peak.qvalue` | `0.05` | narrow 峰 q 值阈值 |
| `peak.broad_cutoff` | `0.05` | broad 峰 cutoff |
| `peak.atac.mode` | `bampe` | `bampe`=ENCODE ATAC v2 做法（按真实片段长度堆叠）；`shifted`=经典 Tn5 偏移配方（`--nomodel --shift -100 --extsize 200`） |
| `peak.atac.shift` / `peak.atac.extsize` | `-100` / `200` | 仅 `mode=shifted` 时生效 |
| `region_flank` | `3000` | 峰注释 flank 距离与 deeptools 信号窗口上下游长度（bp），一处配置同时控制两处 |
| `qc.nsc_rsc` | `false` | SPP 交叉相关 NSC/RSC（较耗时，需 phantompeakqualtools） |
| `qc.frip` | `true` | FRiP（reads in peaks 占比） |
| `qc.deeptools` | `true` | 相关性/PCA/指纹图/片段长/基因区信号 profile |
| `resources` | （整段注释，缺省） | 集群资源覆盖段，见 §4.3 |

### 4.4 校验行为

config 校验在流程解析期集中执行（`workflow/rules/common.smk` 的 `validate_config`）：必需键、子键、类型与取值范围**一次汇总报出**（例如 `dedup.cuttag` 写成字符串会与其它错误一起列出）。参考文件缺失**仅打印警告不中断**——dry-run/lint 场景参考文件常不在本机；正式运行时缺失的参考会在相应规则失败，运行前请按警告逐项确认。

## 5. 运行模式与 assay 路由

### 5.1 seqtype 自动路由

四种 assay 由样本表 `seqtype` 列驱动，同一项目可混型，无需任何启动选项：

| seqtype | 去重（`dedup.<assay>`） | 峰调用规则 | 峰格式 |
|---|---|---|---|
| `chip` | picard 去重（默认开） | `callpeak_narrow`（peak_type=narrow）或 `callpeak_broad`（broad） | narrowPeak / broadPeak |
| `cuttag` | **不去重**（默认关，保留 PCR 重复） | 同 chip 按组峰型路由 | narrowPeak / broadPeak |
| `atac` | picard 去重（默认开） | `callpeak_atac`（`peak.atac.mode` = bampe/shifted） | narrowPeak |
| `faire` | picard 去重（默认开） | `callpeak_atac`（与 atac 同规则） | narrowPeak |

峰调用按 `group` 并行；分组无对照时自动省略 MACS2 `-c`（回退局部 lambda 估计）。每组的信号轨道 `{group}_FE.bw` 由 bdgcmp → bedClip → bedtools sort -g → bedGraphToBigWig 生成（染色体顺序与 chrom.sizes 一致）。

### 5.2 QC 三开关

`config.yaml` 的 `qc:` 段控制三个可选模块（对应规则集在 Snakefile 中条件 include，关闭时不进 DAG）：

| 开关 | 默认 | 产物 |
|---|---|---|
| `qc.frip` | `true` | `5.QC/frip/FRiP_summary.tsv`（并注入 MultiQC 报告） |
| `qc.deeptools` | `true` | `5.QC_deeptools/`：相关性热图、PCA、指纹图、片段长分布、基因区信号 profile |
| `qc.nsc_rsc` | `false` | `5.QC/spp/NSC_RSC_mqc.tsv`（SPP 交叉相关，耗时较长；同时注入 MultiQC） |

无论开关如何，`5.QC/software_versions.yaml`（本次实际使用的工具版本记录）与 MultiQC 汇总报告始终生成；FastQC、bowtie2 比对统计、picard 去重指标自动纳入 MultiQC。

### 5.3 检查与 dry-run

```bash
bash run.sh -P . -n                    # dry-run：构建 DAG、打印将执行的任务，不真正跑
bash run.sh -P . --validate-only       # 解析 workflow + config 后列出规则即退出
bash run.sh -P . --check-software      # 工具 + R + R 包预检
bash run.sh -P . --check-r             # 仅 R 侧预检
```

dry-run 会自动跳过软件预检（不执行工具，无需完整分析环境，仅需 snakemake + python3/PyYAML）。样本表与 config 校验发生在解析期，因此 dry-run 与 `--validate-only` 同样能拦截 §3.2 / §4.4 的错误。

### 5.4 断点续跑与 Snakemake 透传

- 断点续跑：Snakemake 依据输出文件时间戳自动跳过已完成步骤，中断后**原命令重跑即可**；
- profile 已固化 `keep-going: true` 与 `rerun-incomplete: true`；`latency-wait` 默认 90（default/pbs）或 60（sge/slurm），`--latency-wait SEC` 可覆盖；
- 工作目录锁残留（如作业被强杀）用 `bash run.sh -P . --unlock` 清除；
- `--` 之后的参数原样透传给 Snakemake，例如 `bash run.sh -P . -- --rerun-triggers mtime`；
- 启动器日志默认 `snakemake.logs.txt`（`--log FILE` 改），`-q` 降低启动器自身输出。

## 6. 集群提交

### 6.1 四套 profile

profile 把集群参数固化在版本库（`workflow/profile/<name>/config.yaml`，详见 `workflow/profile/README.md`）：

| profile | 调度器 | 行为 |
|---|---|---|
| `default` | 本机/独立服务器 | 无 cluster 串，本地直接执行 |
| `pbs` | PBS (Torque)，snakemake 7.x 经典接口 | `qsub -V -N {rule} -l select=1:ncpus={threads}:mem=<mem> -l walltime=<sec> -j oe`；walltime 用秒避免 `[HH:]MM:]SS` 歧义 |
| `sge` | SGE，snakemake 7.x 经典接口 | `qsub -V -N {rule} -l ncpus={threads} -l h_vmem=<mem> -l h_rt=<sec> -j oe` |
| `slurm` | SLURM，snakemake 7.x 经典接口 | `sbatch --parsable -J {rule} -c {threads} --mem=<mem> --time=<min> -o slurm-{rule}-%j.out` |

四套 profile 均固化 `keep-going: true`、`rerun-incomplete: true`、`printshellcmds: true`。

### 6.2 auto 探测

`--profile auto`（默认，可用环境变量 `RUN_PROFILE` 预设）的探测顺序：

1. PATH 上有 `sbatch` → **slurm**；
2. 有 `qsub` 且设置了 `SGE_ROOT` → **sge**；有 `qsub` 无 `SGE_ROOT` → **pbs**；
3. 都没有 → **default**（本机）。

显式指定的 profile 若对应调度器命令缺失（如 pbs 但无 qsub）会直接报错。`--profile local` 等价于 `default`。

### 6.3 资源模型

集群请求的资源来自三层，靠后者覆盖靠前者：

1. **规则默认值**（§4.3 表）；
2. **项目覆盖**：config 的 `resources:` 段按规则名覆盖 `mem_mb` / `runtime_min`；
3. **全局强制覆盖**：`--memory VALUE`（如 `16G`）覆盖所有规则的内存请求；`--runtime MIN`（分钟）覆盖所有规则的 walltime。

两者仅在集群 profile 下有效（default 本机模式传入会报错）。未覆盖时 cluster 串使用占位符 `{resources.mem_mb}` / `{resources.runtime_sec}` / `{resources.runtime_min}`，由 snakemake 运行期按各规则声明自动填充。

### 6.4 集群相关选项与示例

| 选项 | 适用 profile | 说明 |
|---|---|---|
| `--queue NAME` | pbs / sge | 队列名（slurm 下传入会报错） |
| `--partition NAME` | slurm | 分区名 |
| `--memory VALUE` | pbs / sge / slurm | 全局内存覆盖（`8000`、`8G`、`16GB`、`32GiB` 均可） |
| `--runtime MIN` | pbs / sge / slurm | 全局 walltime 覆盖（正整数分钟） |
| `--sge-mem-resource N` | sge | SGE 内存资源名，默认 `h_vmem` |
| `--scheduler-extra S` | 集群 profile | 追加到 qsub/sbatch 提交命令的原文 |
| `--retries N` | 通用 | 失败任务自动重试次数（默认 0） |
| `--latency-wait SEC` | 通用 | 共享文件系统输出可见性等待 |
| `--max-jobs-per-sec N` / `--max-status-per-sec N` | 通用 | 限制提交/状态查询速率（集群额度紧张时用） |
| `--unlock` | 通用 | 清除 Snakemake 工作目录锁 |

示例（均可照抄）：

```bash
# PBS：workq 队列，全规则 16G/600min，失败重试 1 次
bash run.sh -P . --profile pbs --queue workq --memory 16G --runtime 600 --retries 1

# SGE：all.q 队列，默认按规则资源提交
bash run.sh -P . --profile sge --queue all.q --runtime 720 --retries 2

# SLURM：compute 分区，40 并发
bash run.sh -P . --profile slurm --partition compute --memory 32G -j 40
```

并发上限用 `-j N`（默认 3；四套 profile 中 pbs/sge/slurm 固化 `jobs: 20`，被 `-j` 覆盖）。

### 6.5 环境变量预设

常用选项均可经环境变量预设（命令行显式传参优先）：`RUN_PROFILE`、`CHIP_JOBS`、`CHIP_QUEUE`、`CHIP_PARTITION`、`CHIP_MEMORY`、`CHIP_RUNTIME_MIN`、`CHIP_SGE_MEMORY_RESOURCE`、`CHIP_SCHEDULER_EXTRA`、`CHIP_RETRIES`、`CHIP_LOG`、`CHIP_SOFTWARE_CONFIG`。

### 6.6 PBS 输出回收与 snakemake 8 提示

- PBS 模式下 qsub 的 `.o*` 作业日志落在项目目录根，**运行成功后启动器自动将其回收至 `logs/`**（失败时保留原位便于排查）；
- snakemake ≥ 8 时启动器打印告警：8.x 改用 executor 插件体系（`--cluster` 语义变化），本仓库四套 profile 按 7.x 经典接口编写，**8.x 集群实跑前请先小规模实测**（建议先 `-n` dry-run 再单样本试跑）。

## 8. FAQ

**Q1：样本表报错"缺少列 / 非法字符 / 组内不一致"？**
按 §3.2 逐条对照：6 列表头是否齐全；`sample_id`/`group` 是否含逗号、空格、连续 `__` 或以 `-` 开头；`seqtype`/`role`/`layout`/`peak_type` 拼写是否在白名单内；同一 `group` 内各行三列是否一致；每个 `group` 是否有 `treat`。报错信息含行号，定位到行即可。

**Q2：启动时打印"参考文件不存在（运行前请确认）"？**
这是解析期**警告而非中断**（保证 dry-run/lint 在无参考文件的机器可跑）。正式运行前把 `genome_fa`/`gtf`/`bed`/`chromsize` 改为服务器真实绝对路径，并核对 `genome_size`；参考缺失时 bowtie2 建索引等规则会在执行期失败。

**Q3：不放项目 config 直接运行会怎样？**
配置链回落到仓库 `config/config.yaml`（水稻示例），样本表回落 `grouplist: sample_info.csv`（相对工作目录优先，其次仓库根）。**仓库根的 `sample_info.csv` 是开发示例**，误用它会在样本表校验或 fastq 缺失处报错。正式项目请按 §2 步骤 3/4 在工作目录放样本表与 config。

**Q4：任务被集群杀掉，提示超时/超内存？**
walltime 或内存不足。三种调法（按优先级）：① config `resources.<rule>.runtime_min/mem_mb` 针对性覆盖（§4.3）；② `--runtime` / `--memory` 全局覆盖（§6.3）；③ `--retries N` 让偶发失败自动重试。定位规则：主日志 `snakemake.logs.txt` 找到失败规则名，再到 `logs/<规则相关>.log` 看具体输出。

**Q5：snakemake 8.x 能用集群 profile 吗？**
解析与 dry-run 可用；但 8.x 移除了 `--cluster` 经典语义（改 executor 插件），四套 profile 的 cluster 串按 7.x 编写。启动器检测到 8.x 会打印告警。稳妥做法：集群环境用 `workflow/environment.yaml` 的 snakemake-minimal 7.32.4（参考版本），或 8.x 下先 `--validate-only`/`-n` 验证再小规模实测。

**Q6：集群作业额度/并发受限怎么降速？**
用 `-j N` 降并发上限；`--max-jobs-per-sec` / `--max-status-per-sec` 限制提交与状态查询频率；PBS/SGE 用 `--queue` 指向配额所在队列；仍受限时 `--scheduler-extra` 可追加站点要求的 qsub/sbatch 参数（如账号/项目号）。

**Q7：中断后怎么续跑？锁报错怎么办？**
Snakemake 按产物时间戳跳过已完成步骤，**原命令重跑即可续跑**（profile 已固化 keep-going 与 rerun-incomplete）。若报工作目录锁（`Directory cannot be locked`，多因作业被强杀），执行 `bash run.sh -P . --unlock` 后再跑。

**Q8：CUT&Tag 为什么默认不去重？**
CUT&Tag 文献推荐保留 PCR 重复（Kaya-Okur et al. 2019）：文库扩增循环少、duplicate 含真实信号成分。`dedup.cuttag: true` 可改（按 assay 独立开关，chip/atac/faire 默认去重）。

**Q9：必须有对照组吗？**
不是必须：分组无 control 行时 MACS2 自动省略 `-c`，回退局部 lambda 估计，峰质量会下降。强背景组蛋白修饰（如 H3K27me3 CUT&Tag）与 FRiP 计算均建议提供对照。

**Q10：能跑单端（SE）数据吗？**
当前版本仅支持 PE（样本表 `layout` 固定 `PE`，否则校验报错）。

**Q11：如何换物种？**
替换参考四件套 `genome_fa`/`gtf`/`bed`/`chromsize` + `genome_size`（§4.2），其余流程不变。注意 GTF 需含 gene_id/transcript_id 供 ChIPseeker 构建 TxDb。

**Q12：如何验证新环境部署或流程改动？**
```bash
make check                       # 55 项单元测试 + bash -n 语法检查（无需 snakemake）
make lint                        # 静态检查套件（bash/shellcheck/py/R/yaml/snakemake --lint，缺工具自动跳过）
bash tests/run_test.sh           # 合成数据 dry-run 回归（需 snakemake + python3/PyYAML）
bash tests/run_test.sh --real-run   # 端到端实跑 + 产物断言（服务器验证用，需完整分析环境）
```
测试数据由 `tests/make_testdata.py` 固定种子生成（2 条 100kb 染色体、chip 3 样本 + atac 2 样本），dry-run 默认每样本 50000 读对（CI 传 `--reads 2000`）。改动流程代码前请阅读 [CONTRIBUTING](../CONTRIBUTING.md) 的文档同步 checklist。
