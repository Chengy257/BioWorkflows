# rnaseq-ext - local extension stages for the adopted nf-core/rnaseq route

Consumes the published results of an adopted nf-core/rnaseq run (tag 3.27.0,
revision `a1fcdddd3b826fe46eb46f0479f2ff8a7815af05`) and adds the ratified
local capabilities (scientific decision record:
`nextflow/docs/rnaseq-scientific-decision-record.md`). Every stage is
default-off; enable stages per project with `-params-file` or `--` params.

## Stages

| Stage (param gate) | Capability | Ecosystem module usage |
|---|---|---|
| `featurecounts_quant.enabled` / `quantification_route` | featureCounts gene-count matrix on the published STAR BAMs (legacy counting semantics); the D1 quantification-route switch picks the authoritative matrix | `subread/featurecounts`, `rseqc/inferexperiment` (strand auto) |
| `enrichment.enabled` | clusterProfiler GO (MF/BP/CC) + KEGG over-representation per contrast and direction, plus gseGO on the full ranked list; OrgDb/keyType/KEGG code are params (no species binding) | - (local R modules) |

## Quantification route switch (decision record D1)

Two matrices can exist for one project; the switch declares which is
authoritative:

- `quantification_route = 'salmon'` (default): the adopted run's native
  `{outdir}/salmon/salmon.merged.gene_counts.tsv` is authoritative and is
  emitted as `EXT().out.quant_matrix` (existence verified at run time). The
  featureCounts stage may still run alongside via its own gate.
- `quantification_route = 'featurecounts'`: the featureCounts stage runs
  (its gate is implied) and its merged `count.matrix.tsv` is authoritative;
  `params.ext_gtf` is required.

Downstream consumers (the differentialabundance adapter, the legacy
comparison, the lncRNA handoff) read the emitted `quant_matrix`, so they can
never silently pick the wrong file. `prepare_da_inputs.py --route` mirrors
the switch when writing differentialabundance inputs.

## Consumed adopted-run contract

`ext_results_dir` points at the adopted run's `--outdir`. Expected layout
(pinned tag 3.27.0, default publish paths, verified against a real
test-profile run's output tree on 2026-10-11; every directory/suffix is
overridable via `ext_*` params):

```
{ext_results_dir}/{ext_aligner}/{sample}.markdup.sorted.bam(+.bai)
{ext_results_dir}/{ext_aligner}/samtools_stats/{sample}.sorted.bam.flagstat   (not consumed; listed for completeness)
{ext_results_dir}/salmon/salmon.merged.gene_counts.tsv
```

Markdup BAMs publish unconditionally in 3.27.0 (counting input default =
duplicates removed; set `ext_bam_suffix = '.sorted.bam'` plus
`--save_align_intermeds` on the adopted run to reproduce the legacy
pre-dedup counting semantics). Layout assumes the default
`skip_quantification_merge = false`.

Two project files are consumed alongside:

- `ext_sample_sheet`: the adopted run's nf-core/rnaseq sample sheet (header
  `sample,fastq_1,...`); only the `sample` column is read.
- `ext_metadata`: analysis metadata CSV with header `sample,group[,batch]`
  (one row per sample). This is the D7-configurable analysis metadata the
  DA adapter and enrichment grouping build on; it is NOT provided by
  upstream and must be maintained per project.

## Differentialabundance adapter

`bin/prepare_da_inputs.py` writes the three DA input files from the
switch-selected matrix + the metadata sheet (DA samplesheet, matrix subset
in metadata order, contrasts.yaml with one contrast per non-control group -
reference = control, target = treatment, legacy direction - and optional
blocking factors). See `nextflow/adopted/differentialabundance/README.md`.

## Usage

```bash
# Dry-run baselines (fixtures regenerated by tests/make_fixtures.py):
nextflow run . -profile test -preview        # all stages off: 0 tasks
nextflow run . -profile test_full -preview   # all ratified stages on

# Real run against an adopted run's results:
nextflow run . -profile apptainer \
    -c ~/.nextflow/config \
    --ext_results_dir /path/to/adopted/results \
    --ext_sample_sheet /path/to/samplesheet.csv \
    --ext_metadata /path/to/metadata.csv \
    --params-file my-ext-params.yaml
```

## Tests

`tests/unit/` carries a pytest suite for the locally owned helper scripts
(design doc Section 10.2: "nf-test or appropriate focused tests"): the
legacy strand-code mapping of `parse_strandedness.py`, the raw
featureCounts merge of `merge_featurecounts.py`, the DA adapter emission
(contrast direction, blocking factors, subsetting, failure modes), and the
enrichment DEG split with the legacy thresholds. Run with:

```bash
python -m pytest tests/unit -q
```

nf-test is deliberately deferred: the Nextflow-level wiring is pinned by
the dry-run DAG baselines and fixture real-execution smokes instead (same
rationale as chipseq-ext; see `nextflow/docs/rnaseq-ext-validation-notes.md`).

## Containers

Per-step modular containers (design doc D6): ecosystem modules carry their
own images; local processes declare `quay.io/biocontainers/...` tags
(`python:3.12.12`, reused from the chipseq route, and
`bioconductor-clusterprofiler:4.12.0--r43hdfd78af_1`, pulled into the shared
cache on 2026-10-11). Images are seeded via the validated acquisition recipe
(implementation guidance Section 3.1); unreachable sources are rewritten in
the machine-local container-override configuration.
