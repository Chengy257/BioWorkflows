# AGENTS.md — BioWorkflows repository guide

Snakemake workflow monorepo (github.com/Chengy257/BioWorkflows). Five first-class
workflows — `rna-seq/`, `chip_cuttag_atac_faire/`, `seclip-seq/`, `srna-seq/`,
`bs-seq/` — share one architecture and a `shared/` layer. Target environment:
Linux HPC (SGE/SLURM/PBS) or local execution, Snakemake 7.32.4 (8.x is
unvalidated for the cluster profiles).

## Hard rules

- **English only** in every file: code, comments, docs, commit messages, file
  names. Zero CJK anywhere (a GBK-encoded file once broke the user's Python).
- **LF line endings only** (`.gitattributes` enforces it). Watch Windows editors.
- **Conventional-commit subjects** (`feat|fix|docs|chore|ci(scope): ...`), English.
- **Never commit generated artifacts**: `__pycache__/`, `*.pyc`, and
  `docs/dag_test.svg` (regenerated by `tests/run_test.sh`). Every workflow's
  `.gitignore` carries a "generated docs artifacts" section with
  `docs/dag_test.svg`; seclip-seq v0.1 shipped it tracked by mistake — do not
  repeat that.
- **Cross-project code lives in `shared/`, consumed in place (never copied)**,
  and `shared/` stays project-agnostic. Consumers today: `lib/launcher.sh`,
  `python/bioworkflows_versions.py`, and `python/bioworkflows_runtime.py`
  (the WorkflowSpec framework) are used by all five workflows.
- **Old implementations and process docs are archived to
  `D:\BioWorkflows_archive\` (outside the repo), never tracked.** Implementation
  plans go under its `plans/` directory.
- **Ask the user before any `git push`.**
- **Never use the Windows system Python** (broken by a GBK `.pth`). Use the WSL
  conda envs — `wsl -e bash -lc 'source ~/miniconda3/etc/profile.d/conda.sh &&
  conda activate srna-seq && ...'` (snakemake 7.32.4 lives there; per-project
  analysis envs: `rna-seq`, `seclip-seq`, `bs-seq-pinned`) — or the repo `.venv`
  / chip's `.venv`.

## Per-workflow architecture contract

Every workflow ships (the five current ones are the reference): `run.sh`,
`Makefile` (check/lint/test), `config/{config.yaml, config.template.yaml,
software.yaml, resources.yaml, species.yaml, samples.csv}`, `workflow/{Snakefile,
rules/*.smk, scripts/, environment.yaml, multiqc_config.yaml, profile/{default,
pbs, sge, slurm}}`, `tests/{lint.sh, make_testdata.py, run_test.sh}`,
`docs/{user-guide.md, TODO.md}`, `CHANGELOG.md` (Keep a Changelog format),
`CONTRIBUTING.md`, `LICENSE`, `.gitignore`, `example/{config.yaml, samples.csv}`.

- **Env prefix**: one uppercase prefix per project (RNASEQ / CHIP / BSSEQ /
  SECLIP / SRNA). run.sh env-var fallbacks and the config injection vars
  (`<P>_CONFIG`, `<P>_RESOURCES_CONFIG`, `<P>_EXTRA_CONFIG`, `<P>_SOFTWARE_CONFIG`)
  all use it; keep the pattern when deriving a new launcher.
- **Output layout**: raw reads stay in `1.rawdata/` at the project root; every
  derived artifact goes under the configurable `results_dir` via the `R()` helper,
  in numbered stage dirs (`2.cleandata/`, `3.align/`, `4.*/`, `5.QC/`, ...).
  Stage numbering follows the project's biology — keep it stable once published.
- **Config layering** (later wins): `config/species.yaml` presets → resources
  (`<P>_RESOURCES_CONFIG` or the repo `config/resources.yaml`) → project config
  (`<P>_CONFIG`) → `config.local.yaml` auto-detected in the working directory.
  Species presets fill only keys the project config left unset;
  `species: "none"` skips the merge (synthetic tests rely on this to exercise
  empty-reference paths).
- **common.smk** (included first by every `rules/*.smk`): single-column
  `sample_id` table parsing (`[A-Za-z0-9][A-Za-z0-9._-]*`, no `__`, duplicates
  rejected), parse-time validation that aggregates ALL errors into one report
  (missing reference files only warn), `SAMPLE_WILDCARD` constraint, PE/SE
  raw-read detection, resource helpers `rthreads/rmem/rruntime/rruntime_sec`
  capped by the legacy top-level `threads`, and `TARGETS` aggregation.
- **Rules**: outputs via `R()`, logs under `R("logs/…")`, every rule carries
  `threads:` plus `resources: mem_mb/runtime_min/runtime_sec`. Optional stages
  are parse-time `if`-guarded rule blocks driven by config flags.
- **Software runtime**: a thin `workflow/scripts/runtime_config.py` wrapper over
  `shared/python/bioworkflows_runtime.py` (`WorkflowSpec`). Traps: `tools:`
  accepts only DEFAULT_TOOLS keys (anything else is silently ignored — external
  installs go under `paths:`); keep `"rscript": "Rscript"` in DEFAULT_TOOLS even
  for no-R projects (the framework unconditionally resolves it) but exclude it
  from pipeline_tools so preflight never demands R.
- **Scheduler detection stays per-project** inside each `run.sh` (all five now
  embed the same qsub policy — `SGE_ROOT` present means SGE, otherwise PBS —
  but each launcher owns its copy); moving it into `shared/` is a deliberate
  behavior decision, not a drive-by refactor.

## Testing contract

- `tests/lint.sh`: bash -n + shellcheck + py_compile + `snakemake --lint`
  (missing tools are skipped). Every lint whitelist entry must carry a
  "Known baseline:" comment saying why the warning is accepted.
- `tests/run_test.sh`: synthetic data (fixed seed) → assembled project dir →
  dry-run by default (asserts the DAG contains the key rules) → `--real-run`
  asserts declared outputs exist (needs the full analysis environment). DAG svg
  regeneration is best-effort and never fails the test.
- Dry-run job-count baselines — re-verify after refactors: chip 47, rna-seq deg
  25, seclip-seq 23 (consensus 28 / input-control 45), srna-seq 27 (deg 28 /
  novel-mirna 29), bs-seq 20 (dmr 35).
- Known issues (do not re-litigate): rna-seq CI end-to-end fails at
  `trimAdapter_PE` on the runner (recorded in its CHANGELOG; the user validates
  on the real server); srna DAG-svg generation can fail noisily under `dot`.

## Adding a new workflow — checklist

1. Derive the skeleton from the newest workflow (srna-seq / bs-seq), rename the
   env prefix everywhere, and re-point stages/tools to the new biology.
2. Write `common.smk` validation for YOUR config keys: aggregate errors; treat
   `/path/to/` placeholders as warnings, not errors.
3. `software.yaml`: default executables in `tools:`, external installs in
   `paths:`, large references in `databases:`. `environment.yaml` carries the
   standard header ("Optional all-in-one environment template for a new server.
   This file is NOT created automatically by Snakemake.") with block-form
   `channels:` and pinned versions.
4. Add a CI job in `.github/workflows/ci.yml` following the seclip/srna/bs
   template: setup-python 3.10, `snakemake==7.32.4` + `pulp==2.7.0` + pyyaml
   + pytest, apt shellcheck graphviz, unit tests (`python -m pytest tests -q`
   when the project carries a pytest suite), lint, `bash tests/run_test.sh
   --reads 2000` plus one enabled-stage scenario dry-run per new optional
   stage, DAG artifact upload (uploads read the working tree; `.gitignore` is
   irrelevant to artifact upload).
5. Docs: register the workflow in the ROOT README table; write the per-project
   README / user-guide / TODO (deferred decisions and their rationale) /
   CHANGELOG entry.
6. `.gitignore`: mirror the newest workflow's file — in particular the
   "generated docs artifacts" section (`docs/dag_test.svg`), `__pycache__/`,
   `*.pyc`, results/logs dirs, and `tests/data/` + `tests/work/`.
7. Record the dry-run job-count baseline in this file and the project CHANGELOG.

## Tool ground truths (do not re-derive)

- **Snakemake 7 lint traps**: the "mixed rules and functions" check is a naive
  text regex (`rule .+:` inside comments/strings trips it); `shell.executable()`
  trips the absolutepath lint; output files cannot be functions; `configfile:`
  arguments stay on one line. The lint-green reference is rna-seq.
- **multiqc ≥ 1.21**: a config `title:` RENAMES the report file and a config
  `filename:` does not override it — pin `--filename multiqc_report.html` on the
  CLI (all meta.smk rules do).
- **trim_galore 0.6.x** names every artifact after the FULL input basename:
  trim rules need guarded renames (`mv … 2>/dev/null || true`) to the contract
  paths when raw names are `_R1`-style.
- **umi-tools** was removed from bioconda; the working route is
  `pip install umi-tools==1.1.5` under python 3.9 (the sdist bootstraps
  setuptools 10.0 and cannot build on ≥ 3.10) — seclip-seq pins py3.9 for it.
- **Bismark 0.24** flag/naming surface is reconciled ground truth in
  `bs-seq/docs/TODO.md` §1 (13 WSL real-run rounds) — treat it as the contract.
- **aPEAR is dead upstream** (removed from CRAN + Bioconductor): never make it
  required again; do not trust USTC-mirror-only packages in CI.
- **Parallel `mamba env create` runs collide** (lock crashes): create envs
  sequentially; capture exit status via `PIPESTATUS[0]`, never `$?` after a pipe.
