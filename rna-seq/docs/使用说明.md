# RNA-seq 工作流使用说明

> 更新日期：2026-09-03（对应 v0.8.0，统一软件/R runtime）
> 适用对象：需要在本集群/服务器上运行该流程的分析人员
> v0.8.0 起不再按 rule 自动创建多个 Conda 环境，而是统一复用用户已有的软件 runtime；`config/software.yaml` 管理主 Conda 环境、Rscript/R library、外部工具与数据库。v0.7.0 的 per-rule `threads / mem_mb / runtime` 调度继续保留。

---

## 1. 功能概述

本流程面向 bulk RNA-seq（有参考基因组）数据，通过 `pipeline` 参数提供四种运行模式：

| pipeline | 内容 | 最终产物 |
|---|---|---|
| `upstream` | 质控 → 比对 → 基因定量 | 清洗数据、BAM、count 矩阵、TPM 表 |
| `deg` | upstream + 差异表达 + 富集 + 组间比较 | DEG 结果、GO/KEGG/GSEA、组间比较 |
| `as` | upstream + StringTie 转录本组装/定量（STAR 使用组装优化参数） | 各样本组装 GTF、merged GTF、isoform 定量 |
| `lncrna` | upstream + de novo lncRNA 鉴定 | 候选 lncRNA 集合及其表达矩阵 |

分析主线：`FastQC → Trim Galore（含 FastQC）→ MultiQC 全流程汇总 →（链特异性推断）→ STAR two-pass 比对 → featureCounts 定量 → DESeq2 差异分析 → clusterProfiler GO/KEGG 富集 + GSEA`。

---

## 2. 系统要求

| 依赖 | 说明 |
|---|---|
| Linux（SGE/SLURM 集群或单机） | 自动选择 `qsub` → SGE，`sbatch` → SLURM，否则 local |
| Snakemake ≥ 7 | 必须能从主 runtime 或当前 PATH 找到；当前开发验证版本为 7.32.4 |
| Python 3 + PyYAML | `run.sh` 用于解析 `software.yaml` 与运行前检查 |
| 主软件环境 | 推荐复用已有 `rna-seq` Conda 环境；也支持 `environment.type: system` 直接使用 PATH |
| R | 可来自主 Conda，也可在 `r.rscript` 指定独立 Rscript；R library 由 `r.lib_paths` 控制 |
| lncRNA 外部依赖 | CPC2、CNCI、pfam_scan.pl、Pfam DB、NR DIAMOND DB；CNCI 可单独指定 Python2 |

没有现成环境时，`workflow/environment.yaml` 提供一个**可选的一体化环境模板**：

```bash
mamba env create -f workflow/environment.yaml
Rscript -e 'install.packages("aPEAR", repos="https://cloud.r-project.org")'
```

该命令由用户显式执行；Snakemake 本身不会自动创建或修改软件环境。

## 4. 运行前准备

### 4.1 新建分析项目

```bash
mkdir -p myproject && cd myproject
mkdir -p 1.rawdata
# 放置原始数据：双端 {sample}_1.fastq.gz + {sample}_2.fastq.gz（或 .fq.gz）
#             单端 {sample}.fastq.gz（或 .fq.gz）
cp /path/to/repo/config/config.yaml .
cp /path/to/repo/config/software.yaml .
cp /path/to/repo/example/samples_231107XTL.csv samples.csv   # 或自建样本表
```

⚠️ **样本 ID 命名规则**：不得含 `-`、空格、`/`；避免互为前缀（校验器会对前缀冲突告警）。

### 4.2 样本分组表

列：`id,group`，可选 `layout`（`PE`/`SE`/`auto`，当前以实际文件探测为准，`auto` 即可）：

```csv
id,group,layout
WT_1,control,auto
drugA_1,drugA,auto
```

对照组名由 config 的 `control_group` 指定（默认 `control`）。启动时会自动校验样本表，也可手动运行：
`python3 workflow/scripts/validate_samples.py samples.csv control`

### 4.3 配置文件

复制 `config/config.yaml` 到项目目录，**把 `/path/to/...` 占位符替换为真实路径**：

| 键 | 说明 |
|---|---|
| `pipeline` | 运行模式（run.sh 参数会覆盖它） |
| `results_dir` | 运行产物根目录（默认 `results`，相对运行目录） |
| `SampleListFile` | 样本表（相对运行目录） |
| `control_group` / `threads` | 对照组 / 旧配置兼容的默认线程上限（显式 `resources.<rule>.threads` 可覆盖） |
| `FoldChange` / `padj` / `pca_ntop` | 差异阈值 / PCA 基因数 |
| `batch_correction` | DESeq2 批次校正（默认 `F`；设 `T` 时按 `~ batch + group` 设计，**样本表需含第三列 `batch`**） |
| `species` | `osa` / `hsa`；未显式给出的参考资源回落到 `config/species.yaml` 中该物种的预设 |
| `bed` / `genome` / `gtf` / `annotation_tsv` | 参考资源（顶层显式设置优先于 species.yaml） |
| `star_extra_args` | 追加的 STAR 参数 |
| `resources.<rule>.mem_mb` / `runtime_min` / `threads` | 每规则内存、walltime 与可选线程覆盖；未提供时使用内置默认值 |
| `lncrna.*` | lncRNA 分析参数，仅保留 `gtf`、`gtf_PcGs`、`threads`；软件与数据库已迁至 `software.yaml` |

### 4.3.1 软件与 R runtime：`software.yaml`

项目级 `software.yaml` 优先于仓库默认 `config/software.yaml`；也可用 `run.sh --software FILE` 显式指定。推荐配置示例：

```yaml
environment:
  type: conda
  conda_prefix: "/share/miniconda/envs/rna-seq"   # HPC 推荐使用 prefix
  # conda_name: "rna-seq"                         # 或按环境名解析
  strict: true

r:
  rscript: "/opt/R/4.3.3/bin/Rscript"             # 也可写 Rscript，使用主环境 PATH
  version: "4.3"
  version_check: major_minor
  lib_paths:
    - "/share/Rlibs/4.3"
    - "/home/user/R/4.3/library"
  lib_mode: prepend
  package_sources:
    org.Osativa.eg.db: "/share/db/org.Osativa.eg.db.tar.gz"  # 仅用于安装提示

tools:
  # 普通软件无需逐一填写；以下都是可选 override
  # star: "/opt/STAR/2.7.11b/bin/STAR"
  cpc2: "/share/software/CPC2/bin/CPC2.py"
  pfam_scan: "/share/software/PfamScan/pfam_scan.pl"
  cnci_python: "/share/software/python2/bin/python2"

paths:
  cnci_dir: "/share/software/CNCI"

databases:
  pfam: "/share/database/Pfam"
  nr_diamond: "/share/database/NR/nr.dmnd"
```

解析优先级为：**显式工具路径 > 主 Conda `bin` > 原系统 PATH**。`r.rscript` 独立解析，因此可以使用与主 Conda 不同的 R。`r.lib_paths` 会通过 `R_LIBS_USER` 统一传给 Snakemake rule、`enrich.sh`、`DEGgroupCompare.sh` 及其子 Rscript；`prepend` 不会覆盖 R 自身的 base/site library。

正式运行前建议：

```bash
bash run.sh -p deg -P /path/to/project --software /path/to/project/software.yaml --check-software
bash run.sh -p deg -P /path/to/project --software /path/to/project/software.yaml --check-r
```

`--check-software` 会按 pipeline 检查 executable、R 版本/R 包及 lncRNA 数据库；`--check-r` 只检查 R。流程**不会**在运行中调用 `install.packages()`。缺少自定义 OrgDb 时，请先安装到 `r.lib_paths` 指定目录。

| `strandedness` | 1 | 4000 | 60 |

| `count_merge` | 1 | 4000 | 60 |

| `enrichment` | 2 | 12000 | 360 |
| `deg_compare` | 4 | 12000 | 360 |
| `stringtie` | 8 | 16000 | 360 |
| `gtf_merge` | 4 | 12000 | 240 |

### 4.4 启动脚本 `run.sh`

旧的位置参数调用继续兼容：

```bash
bash run.sh <upstream|deg|as|lncrna> <project_dir> [config.yaml] [jobs]
# 例：bash run.sh deg /path/to/myproject /path/to/myproject/config.yaml 10
```

推荐使用显式参数；完整帮助运行 `bash run.sh --help`：

```bash
# 本地 / 自动调度
bash run.sh -p deg -P /path/to/myproject -c /path/to/myproject/config.yaml -j 20

# 检查统一软件/R runtime
bash run.sh -p deg -P /path/to/myproject --software /path/to/myproject/software.yaml --check-software

# 样本 + 软件/R 全部校验，不启动任务
bash run.sh -p deg -P /path/to/myproject -c /path/to/myproject/config.yaml --validate-only

# dry-run
bash run.sh -p deg -P /path/to/myproject -c /path/to/myproject/config.yaml --dry-run

# SLURM
bash run.sh -p deg -P /path/to/myproject --profile slurm --partition compute --memory 32G -j 40

# SGE
bash run.sh -p deg -P /path/to/myproject --profile sge --queue all.q --runtime 720 --retries 2
```

环境参数：`--software FILE`、`--check-software`、`--check-r`、`--skip-software-check`。调度参数：`--memory VALUE`（全局覆盖每规则内存）、`--runtime MIN`（全局覆盖每规则 walltime）、`--latency-wait SEC`、`--max-jobs-per-sec N`、`--max-status-per-sec N`、`--scheduler-extra "..."`、`--unlock`、`--log FILE`；`--` 后的参数原样传给 Snakemake。大多数长参数同时支持 `--option=value` 写法。

脚本行为：
1. 解析 `software.yaml`，将主 Conda prefix、工具覆盖、`RNASEQ_RSCRIPT` 与 `R_LIBS_USER` 注入当前进程并继承到 SGE/SLURM job；
2. pipeline 与分析配置经 `RNASEQ_PIPELINE` / `RNASEQ_CONFIG` 注入 Snakefile；
3. 正式运行前按 pipeline 做软件/R preflight，并自动校验样本表；当 `batch_correction: "T"` 时强制要求 `batch` 列且每行非空；
4. 自动调度顺序为 SGE（`qsub`）→ SLURM（`sbatch`）→ local；也可经 `--profile` / `RUN_PROFILE` 强制指定；
5. 默认情况下 SGE/SLURM 分别从 `{resources.mem_mb}` 与 `{resources.runtime_*}` 动态申请每规则内存/walltime；`--memory` / `--runtime` 可全局强制覆盖；SGE 内存资源名可用 `--sge-mem-resource` 覆盖；
6. 日志默认写入 `$project_dir/snakemake.logs.txt`，失败时给出退出码、耗时和日志位置。

直接调用 Snakemake 时不会自动解析 `software.yaml`，因此仅建议在所需环境已经激活、PATH/R_LIBS 已自行设置时使用：

```bash
RNASEQ_PIPELINE=deg RNASEQ_CONFIG=$PWD/config.yaml \
  snakemake -s /path/to/repo/workflow/Snakefile --profile /path/to/repo/workflow/profile/sge -j 10
```

## 6. 结果解读（results/ 下）

| 目录/文件 | 内容 |
|---|---|
| `multiqc/multiqc_report.html` | **全流程** QC 汇总（FastQC/Trim Galore/STAR/featureCounts） |
| `software_versions.yaml` | 本次实际解析到的 runtime type/Conda prefix、Rscript/R library、工具路径和数据库路径 |
| `2.cleandata/trim/` | 修剪后 fastq；`{sample}(_1/_2)?_trimming_report.txt` 规范化修剪报告 |
| `2.cleandata/trim/fastqc/` | 修剪后 FastQC 报告（html/zip） |
| `3.align/{sample}_Aligned.sortedByCoord.out.bam(.bai)` | 比对结果（STAR 直出排序 BAM） |
| `3.align/{sample}.strandedness`（及 `_infer_experiment.out`） | 链特异性推断结果 |
| `3.align/mapping_stat.xls` | 汇总比对统计（逐样本解析，ID 完整；Total_Reads 为 PE 读对数） |
| `4.expression/{sample}.count` / `.log` | 单样本 featureCounts 定量与分配统计 |
| `4.expression/count.matrix.tsv` / `GeneExpression_TPM.xls` / `_FPKM.xls` / `GeneCount_Assigned_logs.xls` | 表达矩阵 |
| `5.DEG/Diff_Expr_Analysis_Results/` | 差异分析：聚类热图、PCA（ntop 可配）、各 `{treat}_vs_{control}_DESeq2.output.tsv`、火山图/MA 图、sessionInfo.txt |
| `5.DEG/DEGs/` / `GO_KEGG_enrich/` / `GSEA_enrich_GO/` | DEG 列表及注释 / 富集结果 / GSEA |
| `6.DEGcompare/` | 组间 DEG 集合交集（venn/upset）与交叉富集比较 |
| `4.assembly/`（as 管线） | StringTie 组装、`merged.gtf`、gffcompare 报告、isoform FPKM/TPM |
| `4.LncRNA/` + `5.expression/lncRNA/`（lncrna 管线） | 编码势过滤中间产物、Pfam/NR 命中、`final_lncRNA.fa/gtf`、lncRNA 定量矩阵 |
| `logs/` | 各规则日志 |

## 7. 已知限制与注意事项（v0.8.0）

| # | 事项 | 影响 | 建议 |
|---|---|---|---|
| 1 | KEGG 富集依赖 KEGG REST API 外网访问 | 无外网节点该步自动跳过（GO 结果不受影响） | KEGG 结果在可联网节点补跑；离线 gmt 方案见路线图附录 A |
| 2 | 差异比较命名 `{treat}_vs_{control}` | 对照组名含 `_` 时下游前缀解析可能异常 | 对照组名避免下划线 |
| 3 | 批次校正默认关闭（`batch_correction: "F"`） | 需要批次校正时须显式开启 | config 设 `batch_correction: "T"`，样本表加第三列 `batch`（见 §8 Q2） |
| 4 | `mapping_stat.xls` 的 Total_Reads 取 trim 报告 R1 数（即 PE 读对数） | 与单端样本的"读数"口径不同 | 详细读数以 `*_trimming_report.txt` / `*_Log.final.out` 原文为准 |
| 5 | CNCI 仍依赖 Python2，CPC2/pfam_scan/Pfam/NR 常为服务器外部安装 | lncRNA 环境缺失时对应步骤失败 | 在 `software.yaml` 配置 `cnci_python`、`cnci_dir`、CPC2/PfamScan 与数据库路径，并先运行 `--check-software` |
| 6 | 端到端回归需在已经准备好的统一 RNA-seq 软件环境中执行 | 本仓库不自动安装测试依赖 | `bash tests/run_test.sh --pipeline deg` 一键完成（数据确定性生成，见 §8 FAQ） |

历史审查与改造计划文档已移出仓库归档（不入版本库），需要时从本地归档或 git 历史获取。

## 8. 常见问题（FAQ）

**Q1：单端测序能跑吗？**
能。rawdata 放 `{sample}.fastq.gz`（或 `.fq.gz`），流程按精确文件名自动探测 SE/PE，两套命名在所有管线通用。

**Q2：批次效应怎么处理？**
config 设 `batch_correction: "T"` 并在样本表加第三列 `batch`，DESeq2 即按 `~ batch + group` 设计运行（默认 `"F"` 关闭）。

**Q3：如何只补跑差异分析？**
count 矩阵已存在时，以 `pipeline=deg` 直接运行即可，上游自动跳过。

**Q4：能换物种吗？**
能（osa/hsa）。比对/定量层面更换参考资源；富集层面设置 `species: hsa` 即自动切换 org.Hs.eg.db + ENSEMBL keyType + KEGG hsa（基因 id 自动去版本号）。其他物种需自制 OrgDb 并参照 `workflow/scripts/run_enrichment.R` 扩展。

**Q5：为什么我的差异结果只有 vs control？**
当前设计如此：DESeq2 只输出"各处理组 vs 对照组"（`control_group` 配置）。任意两两比较由 `6.DEGcompare` 基于 DEG 集合做交集/富集比较。

**Q6：已有服务器 Conda 环境怎么复用？**
在项目 `software.yaml` 设置 `environment.type: conda` 和 `conda_prefix`（推荐）或 `conda_name`。无需 `conda activate`；`run.sh` 会把该 prefix 的 `bin` 加到 PATH。若 R 单独安装，再配置 `r.rscript` 与 `r.lib_paths`。可用 `--check-software` 验证解析结果。

**Q7：v0.2.0 之前的入口文件还能用吗？**
不能。旧入口 `rna-seq-workflow/RNA-seq_*.smk` 已废弃并移出仓库归档；请使用 `workflow/Snakefile`（经 `run.sh` 启动），旧代码需要时从本地归档或 git 历史获取。

**Q8：如何验证新环境部署或流程改动？**
```bash
bash tests/lint.sh                       # 静态检查（缺工具自动跳过对应项）
bash tests/test_runtime_config.sh              # runtime/Rscript/Rlib 解析回归
bash tests/test_r_runtime_propagation.sh        # 嵌套 R 调用继承 runtime 回归
bash tests/run_test.sh --pipeline deg    # 端到端回归：合成数据 → dry-run → 运行 → 断言
```
测试数据由 `tests/make_testdata.py` 固定种子生成（2 条 100kb 染色体、60 个模拟基因、2 组 × 2 样本），并附带预期差异基因 truth；断言包括 mapping_stat 对齐与数值校验、count 矩阵形状、DEG 方向校验。`lncrna` 管线因依赖外部工具不在自动测试范围。改动流程代码前请阅读 [CONTRIBUTING](../CONTRIBUTING.md) 的文档同步 checklist。
